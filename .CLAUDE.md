# Quantitative Stock Prediction ML Project

## Project Context

This project develops multi-layer machine-learning models for real-time prediction of US stock-market movements using quantitative-finance features.

The system uses:

- Historical one-minute and aggregated OHLCV, bar count and WAP dta for multiple stocks from interactive broker
- Custom feature-engineering pipelines
- Google Colab for GPU-intensive training
- MLflow for experiment tracking and model registration
- Feast for offline and online feature management
- Docker services for local infrastructure

## Primary Goal

Build, compare, validate, and deploy reproducible machine-learning models for real-time stock-market prediction while preventing data leakage and preserving point-in-time correctness.

## System Architecture

1. **Data Layer:** Stores immutable raw market data and generated datasets.
2. **Feature Engineering:** Transforms one-minute bars into point-in-time quantitative features for multiple stocks.
3. **Model Layer 1:** Predicts the broader 30-minute market direction or regime.
4. **Model Layer 2:** Produces progressively shorter-horizon predictions for 15-minute, 5-minute, and 1-minute intervals.
5. **Experiment Layer:** Records parameters, metrics, artifacts, datasets, and model versions in MLflow.
6. **Feature Store:** Manages validated offline and online features through Feast.
7. **Inference Layer:** Generates real-time predictions using approved production models.

## Data and Feature Rules

- Preserve original timestamps, symbols, OHLCV values bar count and WAP data from interactive broker, and source metadata in raw storage.
- Generate transformed data as new versioned artifacts.
- Discuss about ACD feature because of 
- Ensure every feature is available at or before the prediction timestamp.
- Never use future bars, future aggregates, revised values, or future market information.
- Document missing-bar, market-session, timezone, corporate-action, and symbol-alignment policies.
- Fit scalers, encoders, imputers, and feature selectors using training data only.
- Apply fitted preprocessing artifacts unchanged to validation, test, and inference data.
- Record feature definitions, parameters, versions, and availability timestamps.

## Machine-Learning Rules

- Use chronological splits; never randomly split time-series observations.
- Use walk-forward validation.
- Use purging and embargo when labels or feature windows overlap across dataset boundaries.
- Keep the final holdout period untouched until model selection and tuning are complete.
- Compare complex models against simple baselines.
- Evaluate performance across symbols, time periods, volatility regimes, and market conditions.
- Include commissions, spread, slippage, latency, and turnover in trading evaluation.
- Distinguish predictive metrics from trading and risk metrics.
- Record random seeds and software versions.
- Detect and report target, feature, cross-sectional, survivorship, selection, and look-ahead leakage.
- Do not promote a model using only accuracy or a single backtest result.

## MLflow and Model Artifacts

- Never silently fall back to an unapproved artifact location when `MODELS_DIRECTORY` is missing.
- Use versioned artifact names and never overwrite an approved production model.
- Register a model as production-ready only after validation and explicit approval.
